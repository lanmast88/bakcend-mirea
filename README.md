# Система учёта товаров в доме

Приложение для учёта товаров, хранящихся в доме: продуктов, бытовой
химии, лекарств и других предметов. Позволяет фиксировать, какие товары
есть в наличии, в каком количестве и к какой категории они относятся,
чтобы вовремя пополнять запасы и не покупать лишнее.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django
(ПР5). Предметная область описана объектной моделью: классы `Category`,
`Item`, `User` и операции `Consumption` и `Restocking`. Веб-страницы
формируются на основе этих же объектов, загруженных из JSON-файлов.

## Используемые технологии

- Python 3.10+;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Предметная область

Учёт и контроль запасов внутри домохозяйства: регистрация товаров,
привязка их к категориям, отслеживание количества в наличии и изменение
остатков по мере расходования или пополнения запасов. Каждое изменение
остатка выполняется пользователем и фиксируется в журнале операций.

## Основные сущности

| Сущность | Класс | Назначение |
| --- | --- | --- |
| Категория | `Category` | группа, к которой относится товар |
| Товар | `Item` | товар в доме и его текущий остаток |
| Пользователь | `User` | пользователь системы учёта |
| Операция | `StockOperation`, `Consumption`, `Restocking` | расход или пополнение запаса товара пользователем |

## Классы предметной области

### `Category` — категория товаров

Объект `Category` представляет категорию, к которой относится товар.

Атрибуты:

- `id` — уникальный идентификатор категории;
- `name` — название категории.

Методы:

- `matches()` — сравнение названия категории без учёта регистра;
- `from_data()` — создание категории из данных JSON (`@classmethod`);
- `__str__()` — строковое представление категории.

### `Item` — товар

Объект `Item` представляет товар, хранящийся в доме, и отвечает за свой
остаток.

Атрибуты:

- `id` — уникальный идентификатор товара;
- `name` — название товара;
- `category` — объект `Category`, к которому относится товар;
- `unit` — единица измерения;
- `quantity` — остаток товара (свойство только для чтения);
- `min_threshold` — порог пополнения;
- `date_added` — дата добавления товара.

Методы:

- `consume()` — списание расхода с проверкой наличия;
- `restock()` — пополнение запаса;
- `is_out_of_stock()` — признак того, что товар закончился;
- `is_low_stock()` — признак остатка ниже порога;
- `is_in_category()` — принадлежность товара категории;
- `matches()` — поиск по подстроке названия;
- `stock_status()` — текстовый статус запаса;
- `validate_quantity()` — проверка количества (`@staticmethod`);
- `from_data()` — создание товара из данных JSON и объекта категории
  (`@classmethod`);
- `__str__()` — строковое представление товара.

Остаток хранится в закрытом атрибуте `_quantity` и доступен через
свойство `quantity` (декоратор `@property`). Изменить остаток можно
только методами `consume()` и `restock()`, которые проверяют
корректность операции, — так товар сам отвечает за своё состояние.

### `User` — пользователь

Объект `User` представляет пользователя системы.

Атрибуты:

- `id` — уникальный идентификатор пользователя;
- `username` — имя пользователя;
- `password` — пароль (свойство только для чтения).

Методы:

- `check_password()` — проверка пароля при авторизации;
- `from_data()` — создание пользователя из данных JSON
  (`@classmethod`);
- `__str__()` — строковое представление пользователя.

### `StockOperation`, `Consumption`, `Restocking` — операции с запасом

Объект операции связывает товар и пользователя: он хранит ссылки на
объекты `Item` и `User`, а не только их идентификаторы.

Атрибуты:

- `id` — уникальный идентификатор операции;
- `item` — объект `Item`, с которым выполнена операция;
- `user` — объект `User`, выполнивший операцию;
- `amount` — количество в операции;
- `date` — дата операции;
- `KIND`, `TITLE` — атрибуты класса: код операции в JSON и её название
  для вывода.

Методы:

- `apply()` — применение операции к товару;
- `from_data()` — создание операции из данных JSON и связанных объектов
  (`@classmethod`);
- `__str__()` — строковое представление операции.

`StockOperation` — базовый класс операции. Наследники переопределяют
метод `apply()`: `Consumption` вызывает `item.consume()`, а `Restocking`
— `item.restock()`. Благодаря этому журнал операций обрабатывается
единообразно: вызов `operation.apply()` выполняет нужное действие в
зависимости от класса объекта (полиморфизм).

## Взаимодействие объектов

```text
Category
   ↑
   │ category
  Item ←── item ── StockOperation ── user ──→ User
```

- товар ссылается на объект своей категории: `item.category.name`;
- операция ссылается на объекты товара и пользователя:
  `operation.item.name`, `operation.user.username`;
- через операцию доступны данные связанных объектов:
  `operation.item.category.name`;
- операция изменяет состояние товара вызовом его метода;
- данные приложения хранятся в коллекциях объектов: `list[Category]`,
  `list[Item]`, `list[User]`, `list[StockOperation]`.

## Веб-интерфейс на Django

### Django-проект и приложения

`homestock/` — конфигурационный пакет Django-проекта (создан командой
`django-admin startproject homestock .`, поэтому `manage.py` находится в
корне репозитория рядом с `main.py`). Веб-интерфейс разделён на четыре
Django-приложения, зарегистрированные в `INSTALLED_APPS`:

| Область | Приложение | Почему |
| --- | --- | --- |
| Главная страница | `homepage` | точка входа в систему, задаёт общий вид всех страниц |
| Категории | `categories` | отдельная сущность `Category` из ПР3 |
| Товары | `items` | отдельная сущность `Item` из ПР3 |
| Операции с запасом | `operations` | отдельная сущность `StockOperation` из ПР3 |
| Пользователи | — | Django предоставляет встроенную модель `User` в `django.contrib.auth` |

Отдельное приложение для пользователей не создаётся: в `INSTALLED_APPS`
уже подключено приложение `django.contrib.auth` с собственной моделью
`User`, а своё приложение `users` конфликтовало бы с ним. Работа с
пользователями (регистрация, вход, разграничение доступа) будет
рассмотрена в следующих работах; класс `User` из ПР3 используется как
источник данных для журнала операций.

### Страницы и маршруты

Маршруты распределены по двум уровням: корневой `homestock/urls.py`
подключает маршруты приложений через `include()`, конкретные адреса
описаны в файлах `urls.py` приложений.

| Страница | URL | View-функция | Назначение |
| --- | --- | --- | --- |
| Главная | `/` | `homepage.views.index()` | описание приложения, сводка и навигация |
| Товары | `/items/` | `items.views.items()` | список товаров, упорядоченный по остатку |
| Ниже порога | `/items/low-stock/` | `items.views.low_stock()` | товары с остатком ниже порога пополнения |
| Товар | `/items/<int:item_id>/` | `items.views.item_detail()` | карточка товара и операции по нему |
| Категории | `/categories/` | `categories.views.categories()` | список категорий с числом товаров |
| Категория | `/categories/<int:category_id>/` | `categories.views.category_detail()` | карточка категории и её товары |
| Журнал операций | `/operations/` | `operations.views.operations()` | расход и пополнение запасов |
| Операция | `/operations/<int:operation_id>/` | `operations.views.operation_detail()` | карточка операции и связанные объекты |
| Ошибка 404 | любой неизвестный адрес | `homepage.views.page_not_found()` | собственная страница «страница не найдена» |

В динамических маршрутах используется конвертер `<int:...>`: у объектов
`Item`, `Category` и `StockOperation` числовые идентификаторы. Поэтому
адрес `/items/abc/` не соответствует ни одному маршруту (ошибка
маршрутизации), а `/items/999/` маршруту соответствует, но товар не
найден — страница возвращает код 404 сама.

Маршрут `low-stock/` объявлен в `items/urls.py` выше маршрута
`<int:item_id>/`: Django проверяет шаблоны сверху вниз, поэтому более
специфичные адреса размещаются раньше общих.

### View-функции и формирование HTML

View-функция принимает объект `HttpRequest` и возвращает
`HttpResponse`. Общий каркас страницы собирает вспомогательная функция
`page(title, content)` из приложения `homepage`: кодировка, заголовок
вкладки, метатег `viewport`, подключение Bootstrap 5.3 через CDN,
собственные стили CSS и навигация по разделам. Остальные приложения
импортируют её, поэтому каркас не дублируется, а view-функции
формируют только содержимое страницы.

Оформление выполнено классами Bootstrap (`container`, `navbar`, `card`,
`list-group`, `badge`, `btn`, сетка `row`/`col`) и небольшим набором
собственных CSS-правил в функции `page()`. Статусы выводятся цветными
бейджами: остаток в норме — `bg-success`, ниже порога —
`bg-warning`, товар закончился — `bg-danger`.

### Обработка ошибки 404

Собственная страница 404 подключена в корневом `homestock/urls.py`
строкой `handler404 = "homepage.views.page_not_found"` и действует для
всех приложений сразу. Обработчик срабатывает, когда адрес не подошёл
ни одному маршруту; при `DEBUG = True` вместо него Django показывает
служебную страницу отладки, поэтому проверять собственную страницу
нужно при `DEBUG = False` и заполненном `ALLOWED_HOSTS`.

Если маршрут найден, но объект с указанным идентификатором отсутствует,
view-функция сама возвращает `HttpResponse(..., status=404)` с
сообщением «Товар не найден», «Категория не найдена» или «Операция не
найдена».

### Данные ПР3 в веб-интерфейсе

Веб-слой не дублирует предметную логику: view-функции получают запрос,
загружают объекты средствами ПР3, при необходимости находят конкретный
объект по идентификатору, вызывают методы и функции предметной модели и
формируют HTML-ответ.

| Функция ПР3 | Назначение | Судьба в ПР5 |
| --- | --- | --- |
| `load_data()` | загрузка всех коллекций объектов из JSON | добавлена в ПР5, используется всеми страницами |
| `load_categories()`, `load_items()`, `load_users()`, `load_operations()` | JSON → объекты | используются |
| `find_item_by_id()`, `find_category_by_id()` | поиск объекта по идентификатору | используются страницами карточек |
| `find_operation_by_id()` | поиск операции по идентификатору | добавлена в ПР5, используется страницей операции |
| `find_item_operations()` | операции по товару | используется страницей товара |
| `filter_items_by_category()` | отбор товаров категории | используется страницей категории |
| `sort_items_by_quantity()` | сортировка по остатку | используется страницей товаров |
| `get_low_stock_items()` | товары ниже порога | используется страницей «ниже порога» и сводкой |
| `Item.stock_status()`, `is_low_stock()`, `is_out_of_stock()` | статус запаса | используются в бейджах и карточке |
| `add_item()`, `consume_item()`, `restock_item()`, `get_or_create_category()` | изменение данных | отложены — нужны веб-формы и POST-запросы |
| `authenticate()`, `find_user()`, `check_password()` | авторизация | отложены — нужна аутентификация Django |
| `print_items()`, `print_operations()`, `print_menu()` | вывод в консоль | не используются в вебе, работают в консольной версии |
| `save_categories()`, `save_items()`, `save_operations()` | объекты → JSON | используются консольной версией |

Консольное приложение не удалено: `main.py`, пакет
`home_inventory.models`, `storage.py`, `utils.py`, `views.py`, `cli.py`
и тесты продолжают работать.

## Возможности

### Доступно в веб-интерфейсе (ПР5)

- просмотр сводки по запасам на главной странице;
- просмотр списка товаров с остатками и статусами;
- просмотр карточки товара и операций по нему;
- просмотр товаров, остаток которых ниже порога;
- просмотр списка категорий и товаров выбранной категории;
- просмотр журнала операций расхода и пополнения;
- просмотр карточки операции со связанными товаром и пользователем;
- навигация между всеми разделами.

### Доступно в консольном приложении

- авторизация пользователя;
- просмотр и поиск товаров по названию;
- отбор товаров по категории и сортировка по остатку;
- добавление товара с указанием категории, количества и порога;
- списание расхода и пополнение запаса с записью в журнал;
- вывод товаров ниже порога и журнала операций.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии; в
веб-интерфейсе они появятся после изучения моделей, форм и
аутентификации Django:

- добавление товара и категории через веб-форму;
- списание расхода и пополнение запаса через веб-форму;
- поиск товаров по названию и фильтрация через форму поиска;
- вход пользователя в веб-интерфейсе.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`: категории в
`categories.json`, товары в `items.json`, пользователи в `users.json`,
журнал операций в `operations.json`. Файлы читаются при запуске
консольного приложения и при обработке каждого HTTP-запроса,
перезаписываются после добавления товара или изменения остатка в
консольной версии. Чтение и запись выполняются через контекстный
менеджер `with`, отсутствие файла и некорректный JSON обрабатываются
исключениями.

В JSON хранятся только значения атрибутов и идентификаторы связанных
объектов, а не сами объекты:

```json
{
  "id": 1,
  "name": "Молоко",
  "category_id": 1,
  "unit": "л",
  "quantity": 2,
  "min_threshold": 2,
  "date_added": "2026-09-08"
}
```

```json
{
  "id": 2,
  "kind": "consume",
  "item_id": 1,
  "user_id": 1,
  "amount": 1,
  "date": "2026-09-12"
}
```

При загрузке выполняется обратное преобразование:

```text
JSON
  ↓
category_id / item_id / user_id
  ↓
поиск объектов Category, Item, User
  ↓
создание объектов Item и StockOperation
  ↓
item.category → Category
operation.item → Item
operation.user → User
  ↓
view-функция формирует HTML-страницу
```

Таким образом, JSON используется для хранения данных, объектная модель
— для работы приложения, а Django-представления только отображают
объекты. База данных проекта (SQLite) пока используется лишь
служебными приложениями Django; перенос сущностей в Django ORM
выполняется в следующих работах.

Каталог данных можно переопределить переменной окружения
`HOME_INVENTORY_DATA_DIR`.

## Требования

- Python 3.10+;
- Django 5.2;
- pytest;
- flake8.

Предметная область использует только стандартную библиотеку Python.

`requirements.txt`.

## Запуск тестов

```
uv run pytest -v
```

Тесты проверяют:

- создание объектов `Category`, `Item`, `User` и операций, значения их
  атрибутов и строковые представления;
- методы классов: проверку остатка, расход, пополнение, статус запаса,
  проверку пароля;
- доступ к остатку только для чтения и изменение его методами объекта;
- создание объектов из данных JSON методами `from_data()`;
- полиморфное применение операций `Consumption` и `Restocking`;
- связь операции с объектами товара и пользователя;
- функции работы с коллекциями объектов: добавление, поиск,
  фильтрацию, сортировку, отбор товаров ниже порога;
- преобразование объектов в JSON и восстановление связей при загрузке;
- обработку ошибок ввода и некорректных данных.
