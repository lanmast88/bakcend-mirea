# Система учёта товаров в доме

Консольное приложение для учёта товаров, хранящихся в доме: продуктов,
бытовой химии, лекарств и других предметов. Позволяет фиксировать, какие
товары есть в наличии, в каком количестве и к какой категории они
относятся, чтобы вовремя пополнять запасы и не покупать лишнее.

Предметная область описана объектной моделью: основные сущности
представлены классами `Category`, `Item`, `User` и операциями
`Consumption` и `Restocking`, а коллекции словарей заменены коллекциями
объектов.

## Предметная область

Учёт и контроль запасов внутри домохозяйства: регистрация товаров,
привязка их к категориям, отслеживание количества в наличии и изменение
остатков по мере расходования или пополнения запасов. Каждое изменение
остатка выполняется пользователем и фиксируется в журнале операций.

## Основные сущности

| Сущность | Класс | Назначение |
| --- | --- | --- |
| Категория | `Category` | группа, к которой относится товар |
| Товар | `Item` | товар в доме и его текущий остаток |
| Пользователь | `User` | пользователь системы учёта |
| Операция | `StockOperation`, `Consumption`, `Restocking` | расход или пополнение запаса товара пользователем |

## Классы предметной области

### `Category` — категория товаров

Объект `Category` представляет категорию, к которой относится товар.

Атрибуты:

- `id` — уникальный идентификатор категории;
- `name` — название категории.

Методы:

- `matches()` — сравнение названия категории без учёта регистра;
- `from_data()` — создание категории из данных JSON (`@classmethod`);
- `__str__()` — строковое представление категории.

### `Item` — товар

Объект `Item` представляет товар, хранящийся в доме, и отвечает за свой
остаток.

Атрибуты:

- `id` — уникальный идентификатор товара;
- `name` — название товара;
- `category` — объект `Category`, к которому относится товар;
- `unit` — единица измерения;
- `quantity` — остаток товара (свойство только для чтения);
- `min_threshold` — порог пополнения;
- `date_added` — дата добавления товара.

Методы:

- `consume()` — списание расхода с проверкой наличия;
- `restock()` — пополнение запаса;
- `is_out_of_stock()` — признак того, что товар закончился;
- `is_low_stock()` — признак остатка ниже порога;
- `is_in_category()` — принадлежность товара категории;
- `matches()` — поиск по подстроке названия;
- `stock_status()` — текстовый статус запаса;
- `validate_quantity()` — проверка количества (`@staticmethod`);
- `from_data()` — создание товара из данных JSON и объекта категории
  (`@classmethod`);
- `__str__()` — строковое представление товара.

Остаток хранится в закрытом атрибуте `_quantity` и доступен через
свойство `quantity` (декоратор `@property`). Изменить остаток можно
только методами `consume()` и `restock()`, которые проверяют
корректность операции, — так товар сам отвечает за своё состояние.

### `User` — пользователь

Объект `User` представляет пользователя системы.

Атрибуты:

- `id` — уникальный идентификатор пользователя;
- `username` — имя пользователя;
- `password` — пароль (свойство только для чтения).

Методы:

- `check_password()` — проверка пароля при авторизации;
- `from_data()` — создание пользователя из данных JSON
  (`@classmethod`);
- `__str__()` — строковое представление пользователя.

### `StockOperation`, `Consumption`, `Restocking` — операции с запасом

Объект операции связывает товар и пользователя: он хранит ссылки на
объекты `Item` и `User`, а не только их идентификаторы.

Атрибуты:

- `id` — уникальный идентификатор операции;
- `item` — объект `Item`, с которым выполнена операция;
- `user` — объект `User`, выполнивший операцию;
- `amount` — количество в операции;
- `date` — дата операции;
- `KIND`, `TITLE` — атрибуты класса: код операции в JSON и её название
  для вывода.

Методы:

- `apply()` — применение операции к товару;
- `from_data()` — создание операции из данных JSON и связанных объектов
  (`@classmethod`);
- `__str__()` — строковое представление операции.

`StockOperation` — базовый класс операции. Наследники переопределяют
метод `apply()`: `Consumption` вызывает `item.consume()`, а `Restocking`
— `item.restock()`. Благодаря этому журнал операций обрабатывается
единообразно: вызов `operation.apply()` выполняет нужное действие в
зависимости от класса объекта (полиморфизм).

## Взаимодействие объектов

```text
Category
   ↑
   │ category
  Item ←── item ── StockOperation ── user ──→ User
```

- товар ссылается на объект своей категории: `item.category.name`;
- операция ссылается на объекты товара и пользователя:
  `operation.item.name`, `operation.user.username`;
- через операцию доступны данные связанных объектов:
  `operation.item.category.name`;
- операция изменяет состояние товара вызовом его метода;
- данные приложения хранятся в коллекциях объектов: `list[Category]`,
  `list[Item]`, `list[User]`, `list[StockOperation]`.

Сценарий изменения остатка:

```text
ввод идентификатора товара
        ↓
   поиск Item
        ↓
    ввод количества
        ↓
создание Consumption или Restocking
        │
        ├── item → Item
        └── user → User
        ↓
operation.apply() изменяет остаток товара
        ↓
операция добавляется в журнал
```

## Что изменилось по сравнению с ПР2

В ПР2 товары хранились в словарях (`dict[int, dict]`), а операции над
ними выполняли отдельные функции. В ПР3 те же данные и операции
объединены в объекты.

| Было в ПР2 | Стало в ПР3 |
| --- | --- |
| `items: dict[int, dict]` | `items: list[Item]` |
| `item["quantity"]`, `item["name"]` | `item.quantity`, `item.name` |
| `item["category"]` — строка | `item.category` — объект `Category` |
| `get_stock_status(quantity, min_threshold)` | метод `Item.stock_status()` |
| `consume_item(items, item_id, amount)` изменял словарь | `Consumption(...).apply()` вызывает `Item.consume()`, операция попадает в журнал |
| `restock_item(items, item_id, amount)` изменял словарь | `Restocking(...).apply()` вызывает `Item.restock()` |
| `authenticate()` возвращал `bool` | возвращает объект `User` или `None` |
| `find_user()` возвращал словарь | возвращает объект `User` |
| `add_item()` возвращал идентификатор | возвращает созданный объект `Item` |
| `load_items()` / `save_items()` работали со словарями | преобразуют JSON в объекты и объекты в JSON |
| `format_items_table()` читал ключи словаря | читает атрибуты объектов |

Функции обработки коллекций (`find_items()`,
`filter_items_by_category()`, `sort_items_by_quantity()`,
`get_low_stock_items()`) сохранили назначение и работают с коллекциями
объектов. Функции ввода (`input_text()`, `input_int()`,
`input_date()`) и функции загрузки и сохранения данных остались
обычными функциями.

## Возможности

- авторизация пользователя;
- просмотр и поиск товаров по названию;
- отбор товаров по категории;
- сортировка товаров по остатку;
- добавление товара с указанием категории, количества и порога
  пополнения;
- списание расхода и пополнение запаса с записью в журнал операций;
- вывод товаров, остаток которых опустился ниже порога;
- просмотр журнала операций расхода и пополнения.

и сохранения данных также остались обычными функциями.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`: категории в
`categories.json`, товары в `items.json`, пользователи в `users.json`,
журнал операций в `operations.json`. Файлы читаются при запуске
программы и перезаписываются после добавления товара или изменения
остатка. Чтение и запись выполняются через контекстный менеджер `with`,
отсутствие файла и некорректный JSON обрабатываются исключениями.

В JSON хранятся только значения атрибутов и идентификаторы связанных
объектов, а не сами объекты:

```json
{
  "id": 1,
  "name": "Молоко",
  "category_id": 1,
  "unit": "л",
  "quantity": 2,
  "min_threshold": 2,
  "date_added": "2026-09-08"
}
```

```json
{
  "id": 2,
  "kind": "consume",
  "item_id": 1,
  "user_id": 1,
  "amount": 1,
  "date": "2026-09-12"
}
```

При загрузке выполняется обратное преобразование:

```text
JSON
  ↓
category_id / item_id / user_id
  ↓
поиск объектов Category, Item, User
  ↓
создание объектов Item и StockOperation
  ↓
item.category → Category
operation.item → Item
operation.user → User
```

Таким образом, JSON используется для хранения данных, а объектная
модель — для работы приложения. Преобразование выполняется функциями
модуля `storage.py` и методами `from_data()` классов. Если категория,
товар или пользователь с указанным идентификатором не найдены, объект
не создаётся, а загрузка завершается ошибкой `ValueError`.

Каталог данных можно переопределить переменной окружения
`HOME_INVENTORY_DATA_DIR`.

## Требования

- Python 3.10+;
- pytest;
- flake8.

Основной код использует только стандартную библиотеку Python. Зависимости
описаны в `pyproject.toml` (группа `dev`) и продублированы в
`requirements.txt`.

Установка окружения через [uv](https://docs.astral.sh/uv/):

```
uv sync
```

Установка через pip:

```
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск программы

```
uv run main.py
```

Равнозначные способы запуска: `uv run home-inventory` (точка входа,
объявленная в `pyproject.toml`) и `uv run python -m home_inventory`.

Тестовый пользователь для входа указан в `data/users.json`.

## Запуск тестов

```
uv run pytest -v
```

Тесты проверяют:

- создание объектов `Category`, `Item`, `User` и операций, значения их
  атрибутов и строковые представления;
- методы классов: проверку остатка, расход, пополнение, статус запаса,
  проверку пароля;
- доступ к остатку только для чтения и изменение его методами объекта;
- создание объектов из данных JSON методами `from_data()`;
- полиморфное применение операций `Consumption` и `Restocking`;
- связь операции с объектами товара и пользователя;
- функции работы с коллекциями объектов: добавление, поиск,
  фильтрацию, сортировку, отбор товаров ниже порога;
- преобразование объектов в JSON и восстановление связей при загрузке;
- обработку ошибок ввода и некорректных данных.
